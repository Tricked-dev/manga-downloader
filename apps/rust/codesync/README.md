# codesync

`codesync` is a small Git-to-Git code synchronization tool configured with
Starlark. It is shaped after Copybara, FBShipIt, and Meta-style open source
export flows, while keeping the implementation direct and auditable.

The current implementation focuses on deterministic local syncs:

- Git origins and destinations are operated through `gitoxide`.
- Configuration is Starlark, with Copybara-shaped `core`, `git`, `authoring`,
  `metadata`, and `service` namespaces.
- Starlark type annotations are enabled, along with `typing`, `record`, and
  `enum`.
- CodeSync helper functions return typed Starlark values instead of encoded
  strings.
- Destination state is tracked in commit footers.
- `origin_files` and `destination_files` are glob-based file sets.
- Transformations run in declaration order.
- Sync can replay commits iteratively or squash pending commits into one
  public export commit.
- Pull-request metadata is parsed and shown in plans, even though hosting API
  calls are not implemented yet.

## Status

`codesync` is useful for local path remotes today. It can clone, transform,
commit, and push to local bare destinations through `gitoxide`.

Network Git transport is intentionally not claimed as complete. HTTPS fetch and
push require gitoxide HTTP transport features that are not enabled in the Bazel
build yet. For GitHub smoke tests, clone the GitHub repository with normal Git,
then point `codesync` at that local clone and a local bare destination.

GitHub pull request creation is represented in config and plan output. It does
not call the GitHub API yet.

## Quick Start

Validate a config:

```bash
codesync validate apps/rust/codesync/examples/codesync.star
```

Preview pending work:

```bash
codesync plan apps/rust/codesync/examples/codesync.star
```

Apply and push to the configured destination branch:

```bash
codesync sync apps/rust/codesync/examples/codesync.star --push
```

Run only one workflow:

```bash
codesync sync apps/rust/codesync/examples/codesync.star --workflow demo --push
```

Use a stable work directory while debugging:

```bash
codesync plan apps/rust/codesync/examples/codesync.star --work-dir /tmp/codesync-work
```

## Minimal Config

```python
core.workflow(
    name = "demo",
    origin = git.origin(url = "../internal", fetch = "main"),
    destination = git.destination(
        url = "../public.git",
        fetch = "main",
        push = "codesync/demo",
    ),
    origin_files = glob(["src/**"]),
    destination_files = glob(["third_party/demo/**"]),
    transformations = [
        core.replace(before = "internal", after = "public", paths = glob(["**/*.rs"])),
        core.move("", "third_party/demo"),
    ],
)
```

This config exports files under `src/**`, rewrites matching Rust files, moves
the result under `third_party/demo`, commits it in the destination clone, and
pushes `HEAD` to `refs/heads/codesync/demo` when `--push` is used.

    destination_files = glob(["third_party/testing/**"]),
    authoring = authoring.overwrite(default = "TrashCan69420 <trashcan69666@gmail.com>"),

## Starlark Types

CodeSync enables the Starlark type dialect described by
[starlark-rust types.md](https://github.com/facebook/starlark-rust/blob/main/docs/types.md).
That means configs can use typed function parameters, typed returns, unions,
`typing.Any`, `typing.Callable`, `typing.Iterable`, `record`, and `enum`.

CodeSync also publishes these custom Starlark type globals:

| Type | Produced by | Used by |
| --- | --- | --- |
| `GitRepository` | `git.origin`, `git.github_origin`, `git.destination`, `git.github_pr_destination` | `workflow(origin = ...)`, `workflow(destination = ...)` |
| `FileSet` | `glob`, `core.glob` | `origin_files`, `destination_files`, transformation `paths` |
| `Transformation` | `core.copy`, `core.move`, `core.rename`, `core.remove`, `core.strip`, `core.replace`, `metadata.squash_notes`, `metadata.public_commit_messages` | `transformations = [...]` |
| `Authoring` | `authoring.pass_thru`, `authoring.overwrite`, `authoring.allowed` | `workflow(authoring = ...)` |

These helper functions return real typed Starlark values. Passing a string where
a `GitRepository` is expected fails at the Starlark function boundary instead of
being decoded later.

### Typed Config Example

```python
Mode = enum("ITERATIVE", "SQUASH")
PathSpec = record(include=list[str], exclude=list[str])

def source_repo() -> GitRepository:
    return git.github_origin(url = "../internal", fetch = "main")

def destination_repo() -> GitRepository:
    return git.github_pr_destination(
        url = "../public.git",
        destination_ref = "main",
        pr_branch = "codesync/typed",
        title = "Typed sync",
    )

def files(spec: PathSpec) -> FileSet:
    return glob(spec.include, exclude = spec.exclude)

def public_author() -> Authoring:
    return authoring.overwrite(default = "TrashCan69420 <trashcan69666@gmail.com>")

def transforms() -> list[Transformation]:
    return [
        core.replace(before = "internal", after = "public", paths = glob(["**/*.rs"])),
        core.move("", "third_party/typed"),
    ]

core.workflow(
    name = "typed",
    origin = source_repo(),
    destination = destination_repo(),
    origin_files = files(PathSpec(include = ["src/**"], exclude = [])),
    destination_files = files(PathSpec(include = ["third_party/typed/**"], exclude = [])),
    authoring = public_author(),
    mode = Mode("SQUASH").value,
    transformations = transforms(),
)
```

Records and enums are useful when a config has repeated repository or path
settings. They are normal Starlark values, so they can be passed through helper
functions, validated by annotations, and inspected by field access.

## Workflows

`core.workflow(...)` and the top-level `workflow(...)` alias accept the same
arguments:

| Argument | Type | Default | Meaning |
| --- | --- | --- | --- |
| `name` | `str` | required | Stable workflow identifier. Also written to commit footers. |
| `origin` | `GitRepository` | required | Source repository and ref to export from. |
| `destination` | `GitRepository` | required | Destination repository and ref to update. |
| `origin_files` | `FileSet` | all files | Files kept from the source tree before transformations. |
| `destination_files` | `FileSet` | all files | Destination paths replaced by the transformed tree. |
| `transformations` | `list[Transformation]` | `[]` | Ordered transformation pipeline. |
| `first_commit` | `str` | source head only | Oldest source commit to include on a new destination. |
| `mode` | `str` | `"ITERATIVE"` | `"ITERATIVE"` or `"SQUASH"`. |
| `authoring` | `Authoring` | pass-through | Author policy for generated destination commits. |

If `first_commit` is omitted and there is no previous CodeSync footer in the
destination, CodeSync syncs only the source head. Set `first_commit` when a
first export should include a range of historical commits.

After the first successful sync, CodeSync finds the most recent destination
commit for the workflow by scanning for:

```text
CodeSync-Workflow: <workflow name>
CodeSync-Source-Rev: <source sha>
```

The source rev must still be an ancestor of the current source head. If it is
not, CodeSync stops rather than guessing across a rewritten history.

## Git Repositories

Origin helpers:

```python
git.origin(url = "../internal", fetch = "main")
git.github_origin(url = "../internal", fetch = "main")
git_origin(url = "../internal", ref = "main")
```

Destination helpers:

```python
git.destination(url = "../public.git", fetch = "main", push = "codesync/demo")
git.gerrit_destination(url = "../public.git", destination_ref = "main")
git.github_destination(url = "../public.git", fetch = "main", pr_branch = "codesync/demo")
git.github_pr_destination(url = "../public.git", destination_ref = "main", pr_branch = "codesync/demo")
git_destination(url = "../public.git", ref = "main", push = "codesync/demo")
```

`fetch`, `ref`, and `destination_ref` all select the ref cloned for a workflow.
`push` selects the destination ref updated by `--push`. For GitHub PR-style
destinations, `pr_branch` is also used as the push ref when `push` is omitted.

`git.github_pr_destination` accepts these PR metadata arguments:

```python
title = "Sync demo"
body = "Generated by codesync."
assignees = ["CyclopsBot"]
labels = ["automated-sync"]
draft = True
update_description = True
```

It also accepts several Copybara arguments as no-ops for compatibility:
`partial_fetch`, `allow_empty_diff`, `allow_empty_diff_merge_statuses`,
`allow_empty_diff_check_suites_to_conclusion`, `integrates`, `api_checker`,
`primary_branch_migration`, `checker`, `credentials`, and `github_host_name`.

## File Sets

`glob(include, exclude = None)` creates a `FileSet`.

```python
all_sources = glob(["src/**", "BUILD.bazel"], exclude = ["src/internal_only/**"])
rust_sources = glob(["**/*.rs"])
one_file = glob("README.md")
```

Includes and excludes use repository-relative paths. A string is accepted as a
single include pattern; lists are preferred for non-trivial configs.

## Transformations

Transformations operate on a temporary exported source tree, then the final tree
replaces `destination_files` in the destination checkout.

### `core.copy`

```python
core.copy(".copybara/public", "", paths = glob(["README.md"]))
```

Copies matching files from one subtree to another before later transformations.
The `paths` file set is evaluated relative to the `from` directory.

### `core.move`

```python
core.move("", "third_party/demo")
```

Moves an entire subtree. This is commonly the final transformation in a public
export because it places the transformed source under its destination prefix.

### `core.rename`

```python
core.rename(before = "pkg/old_name.txt", after = "pkg/new_name.txt")
```

Renames one file or directory if it exists. Missing paths are ignored.

### `core.remove`

```python
core.remove(paths = glob(["pkg/private.txt", "src/internal_only/**"]))
```

Deletes matching files from the exported tree.

### `core.strip`

```python
core.strip(paths = glob(["private/**"]))
```

Currently behaves like `core.remove`. It is accepted for Copybara-shaped config
compatibility and may grow distinct semantics later.

### `core.replace`

```python
core.replace(
    before = "//internal/tools",
    after = "//third_party/demo/tools",
    paths = glob(["**/BUILD.bazel", "**/*.bzl"]),
)
```

Performs literal text replacement in matching UTF-8 files. Binary or non-UTF-8
files are left alone.

## Authoring

Authoring controls the author identity on generated destination commits.

```python
authoring.pass_thru()
authoring.overwrite(default = "TrashCan69420 <trashcan69666@gmail.com>")
authoring.allowed(
    default = "TrashCan69420 <trashcan69666@gmail.com>",
    allowlist = ["trusted@example.com"],
)
```

`pass_thru` keeps the source commit author. `overwrite` always uses the default
author. `allowed` keeps source authors only when their email is in the allow
list; otherwise it uses the default author.

The example config uses:

```python
authoring.overwrite(default = "TrashCan69420 <trashcan69666@gmail.com>")
```

## Commit Messages

Generated commits always include these footers:

```text
CodeSync-Workflow: <workflow name>
CodeSync-Source-Rev: <source sha>
GitOrigin-RevId: <source sha>
```

`GitOrigin-RevId` matches the style used by existing Copybara exports.

### Public Message Blocks

Add `metadata.public_commit_messages()` to publish only a marked section from
source commit messages:

```text
Internal implementation details

<BEGIN_PUBLIC>
Publish the allocator wrapper.
<END_PUBLIC>

Private notes stay internal.
```

The public destination message becomes:

```text
Publish the allocator wrapper.
```

If no marker block is present, the public message falls back to:

```text
Internal Change.
```

Markers and fallback text are configurable:

```python
metadata.public_commit_messages(
    begin_marker = "<BEGIN_PUBLIC>",
    end_marker = "<END_PUBLIC>",
    fallback = "Internal Change.",
)
```

### Squash Notes

`metadata.squash_notes(...)` controls the body of a squash export commit.

```python
metadata.squash_notes(
    prefix = "Public export:\n",
    max = 100,
    compact = True,
    show_ref = True,
    show_author = False,
    show_description = True,
    oldest_first = True,
)
```

When `metadata.public_commit_messages()` is also present, squash notes use the
public extracted text or fallback instead of the internal source message.

## Sync Modes

`mode = "ITERATIVE"` replays each pending source commit as its own destination
commit. Empty transformed commits are skipped.

`mode = "SQUASH"` exports the source head and creates one destination commit for
all pending source commits. The squashed message is built from
`metadata.squash_notes(...)`.

## Push Behavior

With `--push`, CodeSync updates the destination push ref after a successful
sync. For local path remotes, it copies newly written loose objects into the
bare remote and then updates the target ref with gitoxide.

For PR-style destinations, the pushed ref is:

1. `push`, when set.
2. `pr_branch`, when `push` is omitted.
3. The destination fetch ref otherwise.

## Testing A Workflow Against GitHub

Until HTTPS gitoxide transport is enabled in Bazel, use a local clone of a
GitHub branch as the CodeSync origin:

```bash
tmp="$(mktemp -d)"
git clone --branch codesync-public-smoke-20260614165004 \
  --single-branch \
  https://github.com/CyclopsBot/testing.git \
  "$tmp/testing"
git init --bare "$tmp/destination.git"
```

Then configure:

```python
core.workflow(
    name = "cyclops-testing-public-smoke",
    origin = git.github_origin(url = "/tmp/.../testing", fetch = "codesync-public-smoke-20260614165004"),
    destination = git.github_pr_destination(
        url = "/tmp/.../destination.git",
        destination_ref = "main",
        pr_branch = "codesync/cyclops-testing-public-smoke",
        title = "CodeSync public smoke",
        draft = True,
    ),
    first_commit = "<oldest smoke source commit>",
    origin_files = glob(["src/**", ".copybara/public/**"]),
    destination_files = glob(["testing/**"]),
    authoring = authoring.overwrite(default = "TrashCan69420 <trashcan69666@gmail.com>"),
    mode = "SQUASH",
    transformations = [
        core.copy(".copybara/public", "", paths = glob(["README.md"])),
        core.remove(paths = glob(["src/internal_only/**"])),
        core.move("", "testing"),
        metadata.squash_notes(prefix = "Public export:\n", oldest_first = True, show_author = False),
        metadata.public_commit_messages(),
    ],
)
```

Seed the bare destination with a `main` branch before running `plan` or `sync`,
because destinations fetch from their configured base ref.

## Design Notes

The Starlark layer is intentionally thin. Helper functions parse into Rust
domain structs immediately, and `workflow(...)` stores those structs directly.
This avoids stringly typed helper values and keeps validation at the config
boundary.

The transformation engine works from full Git trees, not patches. Each pending
source commit is exported to a temporary directory, filtered, transformed, and
then copied into the destination path set. That makes the behavior easy to
reason about and keeps the first implementation independent of patch formats.
